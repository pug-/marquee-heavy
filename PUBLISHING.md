# Publishing MARQUEE Heavy

## Recommended first home: GitHub

1. Create a public repository under your company account, for example `marquee-heavy-font`. Check the public family name before final release; this package does not establish exclusive rights to the name MARQUEE.
2. Add this package: fonts, sources, build scripts, OFL.txt, AUTHORS.txt, FONTLOG.txt, README, specimen and validation notes. Keep beta limitations visible.
3. Create a GitHub Release named `v0.101-beta`, mark it as a pre-release, and attach the ZIP. Invite feedback on letter shapes, spacing and app compatibility.
4. After a type designer/engineer reviews the full character set and automated checks pass, release v1.000 with updated font metadata and release notes.
5. Add a page on your company website with a specimen, the credit, OFL licence and a download link to the GitHub release. That gives the project a clear identity while GitHub holds the source and version history.

GitHub instructions: https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository

## Google Fonts: later, not an automatic listing

Google Fonts is a useful distribution goal, but submission is reviewed, not a self-publishing upload. Its onboarding guide requires a public development repository and engineering quality checks, including FontBakery's googlefonts profile. A derivative needs a clear design purpose and adequate quality; submission does not guarantee acceptance. This beta has NOT been submitted or certified as meeting those requirements.

Guide: https://googlefonts.github.io/gf-guide/onboarding.html
Contribution process: https://github.com/google/fonts/blob/main/CONTRIBUTING.md

## Credit and licence

Keep the Michroma copyright notice and OFL text. Credit MARQUEE AI SYSTEMS for derivative modifications, not for inventing Michroma. OFL permits commercial use and further modifications by others. Do not add restrictions that conflict with it or sell the font by itself. Users do not have to place a visible credit on every design they create with it.

Licence FAQ: https://openfontlicense.org/ofl-faq/

## Before v1.000

- Review name availability and confirm the intended author/publisher wording.
- Test glyphs, punctuation, accented text, combining marks and kerning in real documents.
- Run FontBakery and an OpenType sanitizer; resolve issues.
- Test macOS, Windows, browser and major design/office applications.
- Consider autohinting and a WOFF2 export after engineering review.
- Preserve the original notices and include clear release notes and reproducible sources.

You can distribute this as a beta now with its limitations stated. No accounts, repository or public release were created here.
